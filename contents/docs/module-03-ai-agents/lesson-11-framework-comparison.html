Lesson 11 — Compare Agent Frameworks

Module 03 · AI Agents · understand what the framework automates and what remains your responsibility

Markdown

Why introduce a framework now?

We already built tools, state, loops, routing, retries, budgets, and approvals ourselves. That gives us a concrete baseline. A framework should now earn its place by reducing orchestration complexity without hiding policies we still need to own.

Do not ask “Can the framework build an agent?” Ask “Which responsibilities should the framework own?”
Markdown

Why LangGraph for the comparison?

LangGraph is a low-level orchestration framework aimed at long-running, stateful agent workflows. It can be used independently of the higher-level LangChain agent APIs, which makes it a useful comparison against our explicit Python runner.

We keep the OpenAI Responses API directly in the model node. This isolates the new abstraction to graph orchestration.

The graph

START ↓ model ├── final / stopped → END └── tool request → tool ↓ model

This is essentially the same control loop we previously wrote with a while loop. The difference is that topology describes transitions explicitly.

In [ ]
from langgraph.graph import END, START, StateGraph

builder = StateGraph(GraphState)
builder.add_node("model", model_node)
builder.add_node("tool", tool_node)
builder.add_edge(START, "model")
builder.add_conditional_edges(
    "model",
    route_after_model,
    {"tool": "tool", "end": END},
)
builder.add_edge("tool", "model")

graph = builder.compile()

Markdown

What gets better?

Topology

Possible transitions are explicit rather than scattered across a large loop.

Stateful orchestration

Nodes read state and return updates under a consistent graph model.

Complex branching

Planning, repair, approval, fallback, and verification can become distinct nodes.

Long-running flows

Framework persistence and pause/resume become valuable when runs outlive a single request.

Markdown

What does not become the framework's problem?

We still own tool authorization, argument/domain validation, side-effect safety, retry classification, idempotency, memory selection, cost policy, approval rules, tenant isolation, observability, and evaluation.

Framework abstraction is orchestration, not governance. Moving control flow into graph nodes does not make unsafe tools safe or vague memory policies correct.

Why frameworks are more valuable as complexity grows

A two-node synchronous agent may be clearer as plain Python. A system with investigate → diagnose → repair plan → approval → execute → verify → fallback, plus durable checkpoints and streaming, is where a graph abstraction starts paying for itself.

The right abstraction depends on the shape of the system—not on whether “agents” are fashionable.

Markdown

Frameworks do not erase provider differences

OpenAI, Anthropic, Gemini, and local model stacks differ in tool-call protocols, structured outputs, streaming, usage reporting, reasoning controls, caching, multimodal capabilities, and error behavior. Orchestration abstractions can normalize some of this, but provider-specific behavior still leaks through in real applications.

Markdown

When to use what

Plain Python

Few states, small agent, maximum transparency, custom behavior, or a learning/prototype context.

LangGraph-style framework

Growing state machines, cycles, long-running execution, persistence, approval checkpoints, streaming, and multiple recovery paths.

Higher-level prebuilt agent

Standard architectures where rapid delivery matters more than controlling every orchestration detail.

Deterministic workflow

When model-driven control flow is unnecessary in the first place.
